## دریافت تحلیل نوبیتکس
این نسخه از endpoint عمومی تاریخچهٔ بازار نوبیتکس استفاده می‌کند؛ **API key، رمز حساب یا مجوز معامله نمی‌خواهد**.

با Python 3.11 یا جدیدتر:

    PYTHONPATH=src python -m lili_trader --nobitex
    PYTHONPATH=src python -m lili_trader --nobitex --symbol BTCIRT --resolution 60 --count 100
    PYTHONPATH=src python -m lili_trader --nobitex --symbol ETHIRT --resolution 240 --count 100
    PYTHONPATH=src python -m lili_trader --backtest --symbol BTCIRT --resolution 60 --count 500

پارامترها:
- `--symbol`: نماد بازار نوبیتکس، مثل `BTCIRT` یا `ETHIRT`؛ باید در بازار نوبیتکس موجود باشد.
- `--resolution`: بازهٔ کندل؛ نمونه `60` یعنی ۶۰ دقیقه.
- `--count`: تعداد کندل، از ۱ تا ۵۰۰.

## شبیه‌سازی اهرمی و کنترل ریسک
- شبیه‌ساز اهرمی لانگ/شورت در `src/lili_trader/leverage_paper.py` فقط محاسبات آموزشی انجام می‌دهد.
- `src/lili_trader/leverage_guard.py` پیش از ساخت موقعیت فرضی، دروازهٔ ریسک را روی ارزش کل موقعیت اهرمی (وثیقه × اهرم) اجرا می‌کند.
- آزمون‌های این محافظ در `tests/test_leverage_guard.py` قرار دارد.
- سقف اهرم شبیه‌ساز ۳ برابر است؛ قیمت لیکوییدیشن تخمینی است و فرمول رسمی صرافی محسوب نمی‌شود.
- هیچ سفارش واقعی، اتصال حساب، برداشت یا انتقال وجهی انجام نمی‌شود.
- جزئیات و محدودیت‌ها: [راهنمای فارسی شبیه‌سازی اهرمی](docs/LEVERAGE_PAPER_FA.md).

## برداشت پله‌ای سود در شبیه‌ساز اهرمی

- `src/lili_trader/partial_leverage.py` دو برداشت آزمایشی را مدیریت می‌کند: ۲۵٪ مقدار اولیه در +1R و ۲۵٪ دیگر در +2R؛ ۵۰٪ باقی‌مانده با حد ضرر هوشمند دنبال می‌شود.
- برای جهش قیمت، قیمت هدف مبنای ثبت برداشت است تا نتیجه بیش از حد خوش‌بینانه نشود.
- هر مرحله فقط یک‌بار ثبت می‌شود و کارمزدها در سود خالص لحاظ می‌شوند.
- این قابلیت فقط شبیه‌سازی است؛ جزئیات مارجین و لیکوییدیشن صرافی‌ها همچنان تقریبی‌اند.
- راهنما: [برداشت پله‌ای سود](docs/PARTIAL_LEVERAGE_FA.md).

## اتصال حد ضرر هوشمند به شبیه‌ساز اهرمی

- ماژول `src/lili_trader/managed_leverage.py` موقعیت اهرمیِ فرضی را فقط در صورت رعایت بودجهٔ ریسک و فاصلهٔ امن حد ضرر تا لیکوییدیشن می‌پذیرد.
- ریسک بر اساس ارزش کل موقعیت اهرمی محاسبه می‌شود؛ اگر از بودجه بیشتر باشد، موقعیت رد می‌شود.
- در شبیه‌سازی، لیکوییدیشن پیش از حد ضرر بررسی می‌شود و عبور جهشی از حد ضرر با قیمت بدترِ بازار فرض می‌شود.
- پس از بسته‌شدن، خروج دوباره انجام نمی‌شود. این ماژول سفارش واقعی یا اتصال شبکه ندارد.
- قیمت لیکوییدیشن همچنان تقریبی است؛ Funding، لغزش واقعی، عمق بازار و قواعد اختصاصی صرافی کامل مدل نشده‌اند. این تخمین سقف قطعی زیان نیست.
- راهنما: [مدیریت موقعیت اهرمی با حد ضرر ATR](docs/MANAGED_LEVERAGE_FA.md).

## حد ضرر هوشمند و قفل مرحله‌ای سود
- ماژول مستقل `src/lili_trader/smart_stop.py` حد ضرر را فقط در جهت کاهش ریسک حرکت می‌دهد؛ برای Long فقط رو به بالا و برای Short فقط رو به پایین.
- پله‌های پیش‌فرض: در +1R سر‌به‌سر، +2R قفل +1R، +3R قفل +2R و +4R قفل +3R.
- آزمون‌ها در `tests/test_smart_stop.py` هستند. این قابلیت هنوز به اجرای معامله یا رابط کاربری متصل نیست.
- قفل سود با جابه‌جایی SL، برداشت قطعی سود نیست؛ اجرای واقعی ممکن است به‌علت شکاف قیمت و لغزش بدتر شود.
- راهنما: [حد ضرر هوشمند](docs/SMART_STOP_FA.md).

## بک‌تست تاریخی (فقط شبیه‌سازی)

- راهنما: [راهنمای فارسی بک‌تست](docs/BACKTEST_FA.md).

## امنیت و محدوده
- پروژه به حساب نوبیتکس وارد نمی‌شود، سفارش ثبت نمی‌کند و برداشت/انتقال ندارد.
- کلید API صرافی لازم نیست؛ فعلاً هیچ secret مالی وارد GitHub نکنید.
- امنیت کامل یا «غیرقابل‌هک» بودن قابل تضمین نیست؛ طراحی فعلی عمداً بدون دسترسی مالی است.
- دادهٔ بازار ممکن است تأخیر، اختلال یا خطای منبع داشته باشد. قبل از تصمیم، زمان و صحت داده را بررسی کنید.
- گزارش‌ها آموزشی/تحلیلی‌اند و توصیهٔ قطعی خرید یا فروش نیستند.

## اصل تحلیل
- اندیکاتورها به‌صورت قطعی در Python محاسبه می‌شوند؛ مدل زبانی نباید قیمت یا اندیکاتور را جعل کند.
- اگر داده ناکافی باشد، گزارش باید همین را اعلام کند.
- خبرها و داده‌های بیرونی ورودی قابل اعتماد برای اجرای دستور نیستند.

مشخصات Entry، SL، TP1 و TP2 و اعتبارسنجی سناریوی صعودی/نزولی در [سند طراحی فارسی](docs/TRADE_LEVELS_FA.md) ثبت شده است. در صفحهٔ `docs/chart.html` ورودی‌های دستی و رسم خط‌های Entry، SL، TP1 و TP2 اضافه شده‌اند. صفحه برای نمایش موبایلی بهتر تنظیم شده و خطوط معتبر قبلی با ورود مقادیر نامعتبر پاک نمی‌شوند. کد JavaScript از نظر نحوی بررسی شده، اما هنوز نمایش واقعی روی تبلت و اتصال زندهٔ نوبیتکس آزمایش نشده است. سطوح به‌معنی سیگنال یا توصیهٔ معامله نیست.

## حمایت و مقاومت در هفت تایم‌فریم

- صفحه نمودار، نقشه حمایت و مقاومت ماهانه، هفتگی، روزانه، ۴ ساعته، ۱ ساعته، ۱۵ دقیقه و ۵ دقیقه را کنار هم نمایش می‌دهد.
- پیوت‌ها پس از تأیید کندل‌های بعدی و با دست‌کم دو برخورد خوشه‌بندی می‌شوند؛ محدوده‌ها با ATR تطبیق داده می‌شوند.
- اگر داده یکی از تایم‌فریم‌ها ناقص باشد، تحلیل خودکار ورود متوقف می‌شود. نزدیک بودن ناحیه مخالف تا ۱٫۵R نیز سناریوی فرضی ورود را مسدود می‌کند.
- در تایم‌فریم‌های اصلی، نبود ناحیه مخالف تأییدشده باعث توقف ورود می‌شود؛ شکست ناحیه نیز تا مشاهده بازآزمایی و دو بسته‌شدن کندل در سمت شکست تأیید نمی‌شود.
- این فیلترها محافظه‌کارانه‌اند اما تله بازار را به‌طور قطعی پیش‌بینی نمی‌کنند.
- راهنما: [نقشه حمایت و مقاومت چندتایم‌فریمی](docs/SUPPORT_RESISTANCE_MTF_FA.md).

## نمودار تحت وب

صفحهٔ نمودار تعاملی نوبیتکس در `docs/chart.html` قرار دارد و روی مرورگر موبایل/تبلت اجرا می‌شود. برای انتشار آن با GitHub Pages:
1. در مخزن وارد **Settings → Pages** شوید.
2. در بخش **Build and deployment**، گزینهٔ **Deploy from a branch** را انتخاب کنید.
3. Branch را روی `main` و Folder را روی `/docs` بگذارید و Save کنید.
4. پس از فعال‌شدن Pages، نمودار در آدرس زیر در دسترس خواهد بود:
   `https://raminyaghubi1402-gif.github.io/mobile-/chart.html`

نمودار از API عمومی نوبیتکس در مرورگر داده می‌گیرد؛ ممکن است در برخی شبکه‌ها به علت محدودیت دسترسی/CORS بارگذاری نشود. فایل از کتابخانهٔ Lightweight Charts با CDN استفاده می‌کند، بنابراین برای بارگذاری اولیه اینترنت لازم است.
## تشخیص روند بدون اندیکاتور و سلسله‌مراتب ۱h / ۱۵m / ۵m

- جهت اصلی فقط از ساختار HH+HL یا LH+LL در تایم‌فریم ۱ ساعته تعیین می‌شود؛ روند رنج یا نامشخص یعنی عدم معامله.
- تایم‌فریم ۱۵ دقیقه پایان اصلاح و آماده‌شدن ستاپ را بررسی می‌کند؛ اصلاح خلاف جهت، سیگنال معامله معکوس نیست.
- تایم‌فریم ۵ دقیقه ماشه ورود را تأیید می‌کند؛ اگر ساختار آن هم‌جهت روند ۱h نباشد، لی‌لی صبر می‌کند.
- شکست آخرین کف/سقف تأییدشدهٔ ۱h با بسته‌شدن کندل ۱۵m، ستاپ را باطل می‌کند.
- ماهانه، هفتگی، روزانه و ۴ ساعته فقط زمینه و هشدار نواحی مهم‌اند؛ اختلاف جهت آن‌ها به‌تنهایی جهت اصلی را عوض نمی‌کند.
- ATR فقط برای فاصلهٔ حد ضرر استفاده می‌شود؛ در تشخیص جهت بازار نقشی ندارد.
- تحلیل خودکار از کندل‌های بسته‌شده استفاده می‌کند و هیچ سفارش واقعی ثبت نمی‌کند.
- راهنما: [راهبرد سه‌تایم‌فریمی](docs/THREE_TIMEFRAME_STRATEGY_FA.md) و [تشخیص روند بدون اندیکاتور](docs/PRICE_ACTION_TREND_FA.md). این منطق تضمین سود یا جلوگیری قطعی از زیان نیست.
