# معماری اولیهٔ لی‌لی تریدر

## وضعیت فعلی
این مخزن در مرحلهٔ نمونهٔ آموزشی است. در حال حاضر دادهٔ زنده، مدل زبانی، بروکر یا معاملهٔ واقعی متصل نشده است.

## جریان پیشنهادی
1. Data Adapter: دریافت OHLC و خبر از منبع مجاز؛ ثبت نماد، بازهٔ زمانی، منبع، زمان دریافت و زمان آخرین کندل.
2. Validation: رد دادهٔ ناقص، قیمت نامعتبر یا دادهٔ بیش از حد قدیمی.
3. Indicator Engine: محاسبات قطعی مثل SMA/EMA/RSI و ویژگی‌های کندل. این قسمت نباید به مدل زبانی واگذار شود.
4. Analysis Agents: تحلیل تکنیکال، تحلیل خبر/بنیادی و عامل منتقد. هر عامل باید فقط از داده‌های فراهم‌شده استفاده کند و موارد نامعلوم را مشخص کند.
5. Coordinator: جمع‌بندی فارسی، نمایش اختلاف دیدگاه‌ها، ریسک‌ها و سطح اطمینان بدون ادعای قطعیت.
6. Report: خروجی شامل نماد، بازار، بازه، timestamp، منبع داده، وضعیت تازگی و هشدارها.

## مدل‌های رایگان
- Providerها پشت یک interface مشترک قرار می‌گیرند تا مدل‌ها قابل تعویض باشند.
- قبل از فعال‌سازی هر provider باید شرایط استفاده، محدودیت نرخ، حفظ حریم خصوصی و دسترسی منطقه‌ای بررسی شود.
- «رایگان» به معنی سهمیهٔ نامحدود یا تضمین دسترس‌پذیری نیست.
- در صورت خطای provider، گزارش باید خطا/عدم تحلیل را اعلام کند؛ نباید قیمت یا تحلیل جعلی بسازد.
- کلیدها فقط از secret store خوانده شوند؛ هرگز در log، prompt یا خروجی کاربر چاپ نشوند.

## GitHub Actions
Actions برای CI و اجرای زمان‌بندی‌شده مناسب است، اما سرویس همیشه‌روشن یا real-time نیست. برای اجرای زمان‌بندی‌شده باید محدودیت سهمیه و سیاست‌های GitHub بررسی شود.

## مرز امنیتی نسخهٔ اول
- بدون اتصال به broker، wallet، برداشت یا API معامله.
- مجوز workflow حداقل باشد؛ CI فعلی فقط contents: read دارد.
- دادهٔ بازار و متن خبر ورودی غیرقابل‌اعتماد است؛ هرگونه دستور داخل آن باید به‌عنوان محتوا تلقی شود، نه دستور برای agent.
- هیچ مدل یا agent حق تغییر تنظیمات امنیتی یا اجرای سفارش را ندارد.
