# بازیابی محافظه‌کارانهٔ شکاف کندل‌های ۵ دقیقه‌ای

## قواعد بازیابی

1. ابتدا کندل بومی ۵ دقیقه‌ای از API عمومی نوبیتکس درخواست می‌شود.
2. اگر آن کندل موجود نبود، فقط پنج کندل یک‌دقیقه‌ای نوبیتکس با زمان‌های دقیق و متوالی همان بازه درخواست می‌شوند.
3. کندل ۵ دقیقه‌ای فقط وقتی ساخته می‌شود که هر پنج دقیقه واقعاً موجود باشد:
   - بازشدن: قیمت بازشدن دقیقهٔ اول
   - بیشینه/کمینه: بیشینه/کمینهٔ پنج دقیقه
   - بسته‌شدن: قیمت بسته‌شدن دقیقهٔ پنجم
   - حجم: مجموع حجم پنج دقیقه
4. اگر حتی یک دقیقه مفقود باشد، هیچ کندلی ساخته یا به CSV اضافه نمی‌شود.
5. برای هر کندل تجمیع‌شده، فایل جانبی `*_5_recovery_manifest.jsonl` روش ساخت، پنج timestamp منبع و OHLCV را ثبت می‌کند. جمع‌آوری‌کننده این فایل را نیز به‌صورت idempotent نگه می‌دارد.

## محدودیت منبع جایگزین

دادهٔ والکس یا صرافی دیگر، حتی اگر همان دارایی را در برابر ریال/تومان نمایش دهد، قیمت معامله‌شده در بازار نوبیتکس نیست. چنین داده‌ای فقط برای مقایسهٔ مستقل مناسب است و نباید به‌عنوان کندل BTCIRT/ETHIRT نوبیتکس وارد تاریخچهٔ اصلی شود.

## نتیجهٔ بررسی شکاف فعلی

در دادهٔ ثبت‌شدهٔ مخزن، کندل ۵ دقیقه‌ای با timestamp برابر `1795268700` برای هر دو نماد BTCIRT و ETHIRT وجود ندارد. در نمونهٔ یک‌دقیقه‌ای ETHIRT، پس از timestamp `1795268400` دادهٔ بعدی در `1795269240` است؛ بنابراین ۱۳ دقیقهٔ میانی ثبت نشده‌اند و پنج کندل کامل یک‌دقیقه‌ای برای بازسازی آن کندل ۵ دقیقه‌ای در فایل موجود نیست.

این قابلیت تلاش می‌کند دادهٔ یک‌دقیقه‌ای را مستقیماً از API عمومی نوبیتکس نیز بازیابی کند. تا زمانی که پنج ردیف دقیق از API دریافت نشود، شکاف حل‌شده تلقی نمی‌شود و بک‌تست باید fail-closed باقی بماند.

**این سازوکار فقط برای دادهٔ تاریخی و بک‌تست است؛ هیچ سفارش یا عملیات مالی انجام نمی‌دهد.**
