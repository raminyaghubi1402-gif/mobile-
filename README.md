# لی‌لی تریدر | Li-Li Trader

دستیار فارسی تحلیل بازار؛ نسخهٔ فعلی فقط تحلیل و آموزش است و هیچ معامله‌ای انجام نمی‌دهد.

## محدودهٔ سبک نسخهٔ تبلت

نسخهٔ فعلی فقط روی دو بازار **BTCIRT (بیت‌کوین)** و **ETHIRT (اتریوم)** در نوبیتکس متمرکز است. بازارهای دیگر از رابط اصلی حذف شده‌اند تا انتخاب‌ها و بار کاری غیرضروری زیاد نشود. نمودار فقط برای نماد انتخاب‌شده داده می‌گیرد؛ هیچ دریافت هم‌زمانی برای چند بازار انجام نمی‌شود. تایم‌فریم‌های اصلی تحلیل ۱ ساعت، ۱۵ دقیقه و ۵ دقیقه هستند و داده‌های زمینه‌ای محدود فقط برای همان نماد انتخاب‌شده دریافت می‌شوند. این پروژه برای اجرای سبک در مرورگر تبلت طراحی می‌شود؛ مدل زبانی محلی سنگین، پردازش دائمی پس‌زمینه و معاملهٔ واقعی جزو محدوده نیستند.

## دریافت تحلیل نوبیتکس
این نسخه از endpoint عمومی تاریخچهٔ بازار نوبیتکس استفاده می‌کند؛ **API key، رمز حساب یا مجوز معامله نمی‌خواهد**.

با Python 3.11 یا جدیدتر:

    PYTHONPATH=src python -m lili_trader --nobitex
    PYTHONPATH=src python -m lili_trader --nobitex --symbol BTCIRT --resolution 60 --count 100
    PYTHONPATH=src python -m lili_trader --nobitex --symbol ETHIRT --resolution 240 --count 100
    PYTHONPATH=src python -m lili_trader --backtest --symbol BTCIRT --resolution 60 --count 500
    PYTHONPATH=src python -m lili_trader --price-action-backtest --symbol BTCIRT --count 500

پارامترها:
- `--symbol`: نماد بازار نوبیتکس، مثل `BTCIRT` یا `ETHIRT`؛ باید در بازار نوبیتکس موجود باشد.
- `--resolution`: بازهٔ کندل؛ نمونه `60` یعنی ۶۰ دقیقه.
- `--count`: تعداد کندل، از ۱ تا ۵۰۰.

- آزمون‌های این محافظ در `tests/test_leverage_guard.py` قرار دارد.
- سقف اهرم شبیه‌ساز ۳ برابر است؛ قیمت لیکوییدیشن تخمینی است و فرمول رسمی صرافی محسوب نمی‌شود.
- هیچ سفارش واقعی، اتصال حساب، برداشت یا انتقال وجهی انجام نمی‌شود.
- جزئیات و محدودیت‌ها: [راهنمای فارسی شبیه‌سازی اهرمی](docs/LEVERAGE_PAPER_FA.md).

- هر مرحله فقط یک‌بار ثبت می‌شود و کارمزدها در سود خالص لحاظ می‌شوند.
- این قابلیت فقط شبیه‌سازی است؛ جزئیات مارجین و لیکوییدیشن صرافی‌ها همچنان تقریبی‌اند.
- راهنما: [برداشت پله‌ای سود](docs/PARTIAL_LEVERAGE_FA.md).

## اتصال حد ضرر هوشمند به شبیه‌ساز اهرمی

- ماژول `src/lili_trader/managed_leverage.py` موقعیت اهرمیِ فرضی را فقط در صورت رعایت بودجهٔ ریسک و فاصلهٔ امن حد ضرر تا لیکوییدیشن می‌پذیرد.
- ریسک بر اساس ارزش کل موقعیت اهرمی محاسبه می‌شود؛ اگر از بودجه بیشتر باشد، موقعیت رد می‌شود.
- در شبیه‌سازی، لیکوییدیشن پیش از حد ضرر بررسی می‌شود و عبور جهشی از حد ضرر با قیمت بدترِ بازار فرض می‌شود.
- پس از بسته‌شدن، خروج دوباره انجام نمی‌شود. این ماژول سفارش واقعی یا اتصال شبکه ندارد.
- قیمت لیکوییدیشن همچنان تقریبی است؛ Funding، لغزش واقعی، عمق بازار و قواعد اختصاصی صرافی کامل مدل نشده‌اند. این تخمین سقف قطعی زیان نیست.
- راهنما: [مدیریت موقعیت اهرمی با حد ضرر ATR](docs/MANAGED_LEVERAGE_FA.md).

## حد ضرر هوشمند و قفل مرحله‌ای سود
- ماژول مستقل `src/lili_trader/smart_stop.py` حد ضرر را فقط در جهت کاهش ریسک حرکت می‌دهد؛ برای Long فقط رو به بالا و برای Short فقط رو به پایین.
- پله‌های پیش‌فرض: در +1R سر‌به‌سر، +2R قفل +1R، +3R قفل +2R و +4R قفل +3R.
- آزمون‌ها در `tests/test_smart_stop.py` هستند. این قابلیت هنوز به اجرای معامله یا رابط کاربری متصل نیست.
- قفل سود با جابه‌جایی SL، برداشت قطعی سود نیست؛ اجرای واقعی ممکن است به‌علت شکاف قیمت و لغزش بدتر شود.
- راهنما: [حد ضرر هوشمند](docs/SMART_STOP_FA.md).

## موتور چندمدلی هوش مصنوعی و بازبینی چندعاملی

- درگاه قابل‌تنظیم چند ارائه‌دهندهٔ سازگار با OpenAI Chat Completions در `ai_router.py`.
- سه نقش متوالی: تحلیل‌گر، منتقد/کنترل ریسک و هماهنگ‌کننده در `ai_team.py`.
- اجرای اختیاری: `PYTHONPATH=src python -m lili_trader --market-analysis --symbol BTCIRT --ai-review`.
- ارائه‌دهندگان و نام متغیر محیطی کلیدها از `LILI_AI_PROVIDERS` خوانده می‌شوند؛ هیچ کلیدی در مخزن نیست.
- محدودیت نرخ، cooldown، cache موقت، مهار درخواست تکراری و fallback محلی وجود دارد.
- مدل زبانی اجازهٔ تغییر تصمیم موتور قطعی یا ساخت دادهٔ بازار را ندارد.
- راهنما و محدودیت‌ها: [پیکربندی مدل‌های هوش مصنوعی](docs/AI_PROVIDERS_FA.md).

## ژورنال معاملات آزمایشی و گزارش عملکرد

- ماژول `paper_session.py` چرخهٔ باز/بسته‌شدن یک موقعیت Long نقدی را به ژورنال محلی append-only متصل می‌کند.
- اگر ثبت ژورنال پیش از commit حساب شکست بخورد، موجودی و موقعیت حساب شبیه‌سازی تغییر نمی‌کند.
- گزارش فارسی عملکرد از روی ژورنال JSONL ساخته می‌شود؛ شامل سود خالص پس از کارمزد/لغزش، نرخ برد، ضریب سود، امید ریاضی، میانگین R و افت سرمایه.
- اجرای گزارش: `PYTHONPATH=src python -m lili_trader --journal-report data/paper/trades.jsonl --journal-starting-equity 1000000`
- بازیابی: `PaperTradeSession.restore(journal)` موجودی و موقعیت را با replay رویدادهای دارای snapshot بازسازی و تطبیق می‌کند؛ snapshot ناسازگار یا دستکاری‌شده رد می‌شود.
- اتصال بک‌تست: گزینهٔ `--backtest-journal PATH` معاملات بسته‌شدهٔ موتور ۱h/۱۵m/۵m را با شناسهٔ قطعی به ژورنال جداگانه وارد می‌کند؛ اجرای دوباره تکراری نمی‌سازد.
- راهنما: [ژورنال و گزارش معاملات آزمایشی](docs/PAPER_JOURNAL_FA.md).

## دفتر تصمیم‌ها و کالبدشکافی معاملات

- ماژول `src/lili_trader/decision_journal.py` تصمیم‌های BUY/SELL/WAIT را پیش از اجرا ثبت می‌کند؛ تصمیم WAIT هم ثبت می‌شود تا فرصت‌های ردشده و فیلترهای بیش‌ازحد سخت قابل بررسی باشند.
- هر تصمیم با نماد، زمان داده، نسخهٔ استراتژی، دلیل، شواهد ۱h/۱۵m/۵m و سطوح ورود/حدضرر/هدف/ریسک ذخیره می‌شود.
- پس از پایان معامله، یک بازبینی مستقل با برچسب خطا، علت ریشه‌ای و اقدام اصلاحی به شناسهٔ تصمیم متصل می‌شود.
- زنجیرهٔ SHA-256 تغییر یا حذف تصادفی رویدادها را آشکار می‌کند؛ این سازوکار امضای دیجیتال یا حفاظت در برابر بازنویسی عمدی کل فایل نیست.
- گزارش دفتر: `PYTHONPATH=src python -m lili_trader --decision-journal-report data/paper/decisions.jsonl`.
- راهنما: [دفتر تصمیم‌ها و کالبدشکافی معاملات](docs/DECISION_REVIEW_FA.md).
- بک‌تست ساختار قیمت می‌تواند برای هر کندل بسته‌شدهٔ ۵ دقیقه‌ای تصمیم BUY/SELL/WAIT را به دفتر اضافه کند: `--price-action-backtest --decision-journal PATH`. هر اجرا شناسهٔ جدا دارد؛ خطای ثبت، بک‌تست را متوقف می‌کند.
- گزارش دفتر: `--decision-journal-report PATH`. در حالت ممیزی نقدی، SELL استقراضی به WAIT تبدیل می‌شود.
- این اتصال هنوز پایش زندهٔ شبانه‌روزی نیست و حداقل ارزش/مقدار سفارش نوبیتکس را اعمال نمی‌کند؛ بنابراین هنوز نتیجهٔ اجرای قابل‌معامله با ۱۰ دلار نیست.

## بک‌تست اختصاصی ساختار قیمت ۱h / ۱۵m / ۵m

- فرمان `--price-action-backtest` داده‌های عمومی BTCIRT (یا نماد انتخابی) را جداگانه در سه تایم‌فریم دریافت می‌کند.
- جهت ۱h، ستاپ ۱۵m و ماشهٔ ۵m را مطابق راهبرد بدون اندیکاتور ارزیابی می‌کند؛ BUY و SELL هر دو فقط در شبیه‌ساز و بدون اهرم هستند.
- ورود پس از بسته‌شدن سیگنال و در بازشدن کندل بعدی انجام می‌شود؛ کندل‌های بالاتر تا پیش از بسته‌شدنشان استفاده نمی‌شوند.
- راهنما و محدودیت‌ها: [بک‌تست اختصاصی سه‌تایم‌فریمی](docs/PRICE_ACTION_BACKTEST_FA.md).
- برای نمونهٔ تاریخی بهتر، `--count 500` را انتخاب کنید؛ API عمومی در هر صفحه حداکثر ۵۰۰ کندل می‌دهد؛ دریافت تاریخچهٔ چندصفحه‌ای تا ۵۰۰۰ کندل پشتیبانی می‌شود. بازهٔ ۵ دقیقه‌ای ۲۰۰۰ کندل حدود ۷ روز است و برای نتیجه‌گیری آماری بلندمدت کافی نیست.

## امنیت و محدوده
- پروژه به حساب نوبیتکس وارد نمی‌شود، سفارش ثبت نمی‌کند و برداشت/انتقال ندارد.
- کلید API صرافی لازم نیست؛ فعلاً هیچ secret مالی وارد GitHub نکنید.

- دادهٔ بازار ممکن است تأخیر، اختلال یا خطای منبع داشته باشد. قبل از تصمیم، زمان و صحت داده را بررسی کنید.
- گزارش‌ها آموزشی/تحلیلی‌اند و توصیهٔ قطعی خرید یا فروش نیستند.

## اصل تحلیل

## تشخیص روند بدون اندیکاتور و سلسله‌مراتب ۱h / ۱۵m / ۵m

- جهت اصلی فقط از ساختار HH+HL یا LH+LL در تایم‌فریم ۱ ساعته تعیین می‌شود؛ روند رنج یا نامشخص یعنی عدم معامله.
- تایم‌فریم ۱۵ دقیقه پایان اصلاح و آماده‌شدن ستاپ را بررسی می‌کند؛ اصلاح خلاف جهت، سیگنال معامله معکوس نیست.
- تایم‌فریم ۵ دقیقه ماشه ورود را تأیید می‌کند؛ اگر ساختار آن هم‌جهت روند ۱h نباشد، لی‌لی صبر می‌کند.
- شکست آخرین کف/سقف تأییدشدهٔ ۱h با بسته‌شدن کندل ۱۵m، ستاپ را باطل می‌کند.
- ماهانه، هفتگی، روزانه و ۴ ساعته فقط زمینه و هشدار نواحی مهم‌اند؛ اختلاف جهت آن‌ها به‌تنهایی جهت اصلی را عوض نمی‌کند.
- ATR فقط برای فاصلهٔ حد ضرر استفاده می‌شود؛ در تشخیص جهت بازار نقشی ندارد.
- تحلیل خودکار از کندل‌های بسته‌شده استفاده می‌کند و هیچ سفارش واقعی ثبت نمی‌کند.
- راهنما: [راهبرد سه‌تایم‌فریمی](docs/THREE_TIMEFRAME_STRATEGY_FA.md) و [تشخیص روند بدون اندیکاتور](docs/PRICE_ACTION_TREND_FA.md). این منطق تضمین سود یا جلوگیری قطعی از زیان نیست.


## تاریخچهٔ بازار
GitHub Actions هر روز دادهٔ عمومی BTCIRT و ETHIRT را در تایم‌فریم‌های ۵ دقیقه، ۱۵ دقیقه، ۱ ساعت، ۴ ساعت و روزانه جمع می‌کند و در `data/history/` نگه می‌دارد. این کار به‌مرور تاریخچهٔ بک‌تست را از محدودیت بازهٔ کوتاه API عمومی فراتر می‌برد؛ پس از ثبت دادهٔ جدید، بک‌تست دو نماد نیز خودکار اجرا می‌شود. هیچ توکن حساب یا سفارش معاملاتی استفاده نمی‌شود.
