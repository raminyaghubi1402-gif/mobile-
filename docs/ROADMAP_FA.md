# نقشه‌راه لی‌لی تریدر

## هدف پروژه
ساخت دستیار فارسی تحلیل بازار برای فارکس و رمزارز؛ مناسب استفاده از موبایل/تبلت و تا حد ممکن رایگان.

## محدوده نسخه اول
- فقط تحلیل و آموزش؛ بدون اتصال به بروکر، کیف پول یا اجرای معامله.
- نمایش تحلیل‌ها با زمان ثبت و منبع داده.
- اعلام صریح داده‌های قدیمی، ناقص یا نامطمئن.
- گزارش فارسی قابل فهم برای مبتدیان.
- معماری قابل توسعه برای استفاده از چند ارائه‌دهنده مدل هوش مصنوعی، با اولویت گزینه‌های رایگان و امکان تعویض ارائه‌دهنده.

## اصول ایمنی و امنیت
- هیچ کلید بروکر، کیف پول یا دسترسی برداشت در پروژه اولیه ذخیره نشود.
- کلیدهای API فقط در GitHub Actions Secrets یا سرویس امن مشابه؛ هرگز در کد، فایل تنظیمات عمومی یا لاگ.
- مدل زبانی نباید قیمت، خبر یا اندیکاتور را جعل کند؛ داده بازار از منبع مشخص دریافت و اعتبارسنجی شود.
- خروجی‌ها توصیه قطعی مالی نیستند؛ ریسک و عدم قطعیت باید واضح بیان شود.
- امنیت صددرصدی قابل تضمین نیست؛ دسترسی‌ها باید حداقلی و قابل بازبینی باشند.

## معماری پیشنهادی
1. گردآورنده داده بازار و خبر با ذکر منبع و زمان.
2. محاسبات قابل آزمون برای شاخص‌ها و تحلیل تکنیکال، جدا از مدل زبانی.
3. عامل تحلیل تکنیکال.
4. عامل بررسی اخبار و عوامل بنیادی.
5. عامل منتقد برای یافتن تناقض‌ها و ریسک‌ها.
6. هماهنگ‌کننده برای جمع‌بندی فارسی.
7. رابط ارائه‌دهنده مدل با امکان افزودن/حذف مدل‌ها و مدیریت محدودیت‌ها.

## مراحل اجرا

### مرحله ۱ — پایه و مستندسازی
- تعریف ساختار پروژه، تنظیمات، قالب گزارش و سیاست امنیت.
- افزودن این نقشه‌راه به مخزن.

### مرحله ۲ — نمونه تحلیل بدون مدل
- دریافت داده بازار از منبع معتبر.
- محاسبه چند شاخص پایه و تولید گزارش ساده.
- آزمون داده ناقص، قدیمی و خطاهای شبکه.

### مرحله ۳ — اتصال مدل‌های رایگان
- طراحی رابط مشترک برای ارائه‌دهندگان.
- پشتیبانی از چند مدل در صورت دسترسی و سهمیه رایگان.
- مدیریت خطا، محدودیت نرخ، زمان انتظار و جایگزین محلی.
- عدم وابستگی دائمی به یک API.

### مرحله ۴ — تحلیل چندعاملی
- تحلیل تکنیکال، خبر/بنیادی و نقد ریسک.
- بررسی اختلاف نظر عامل‌ها و ارائه دلایل.
- گزارش فارسی همراه با منبع و زمان داده.

### مرحله ۵ — رابط موبایل و آزمون
- خروجی مناسب نمایش در موبایل و تبلت.
- آزمون‌های خودکار، بررسی امنیت وابستگی‌ها و مستندات نصب.

## محدودیت زیرساخت رایگان
GitHub Actions برای ساخت، آزمون و اجرای زمان‌بندی‌شده مناسب است؛ اما جایگزین سرور همیشه‌روشن نیست. زمان اجرا، سهمیه و دسترسی سرویس‌های رایگان ممکن است تغییر کند. اجرای مداوم یا گزارش‌دهی لحظه‌ای نیازمند بررسی زیرساخت جداگانه است.

## معیارهای پذیرش نسخه اولیه
- هیچ معامله واقعی یا اتصال به بروکر انجام نشود.
- قیمت و خبر بدون منبع/زمان نمایش داده نشود.
- کلیدها در مخزن و لاگ‌ها ظاهر نشوند.
- تست‌های خطا و داده قدیمی وجود داشته باشند.
- گزارش فارسی، قابل فهم و همراه با ریسک‌ها باشد.
